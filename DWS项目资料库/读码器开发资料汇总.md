## 2. 读码器能力（官方手册确认，不含推测）

- 读码器**自带解码**，直接以文本形式输出条码内容，上位机不需要解码库、不需要华睿 SDK 也能工作。
- 一维码：Code39 / Code93 / Code128 / CodaBar / EAN8 / EAN13 / UPCA / UPCE / ITF25 / 2of5 / standard25 / GS1-128。
- 二维码：QR / Data Matrix / Micro QR / GS1 DM / GS1 QR / Vericode（Vericode 需额外许可）。
- 单图最多解 **128 个码**；支持 16 个 ROI 区域，可按区域名称/坐标排序输出。
- 支持最多 **8 组参数切换**（自动换线用，v1 可不管）。
- 支持码质量评价：ISO/IEC 29158(AIM-DPM)、15415、15416。
- 触发：自由运行 / 单帧 / 多帧 / 电平 / 动检；触发源：软件 / Line0 / Line1 / TCP / 串口。
- 通讯协议：SDK、TCP Client、TCP Server、FTP、RS232、Profinet、Modbus TCP、EtherNet/IP、MC(SLMP)、FINS/UDP、FINS/TCP。
- **多设备组网**：主相机 + 最多 16 台从相机；主相机可设“输出绑定时间”、“从相机触发模式（主动/被动）”——这是官方为六面扫这类多相机场景提供的聚合方案。
- 存图：OK/NG 图片可通过 FTP 上传到上位机目录（可配存图条件）。
- 硬件：12 芯 M12（3 路光耦隔离输入、3 路光耦隔离输出、RS232 收发），8 芯 M12 千兆网口；供电 DC 9~26V；正确装镜头罩可达 IP67。

## 3. 通讯实测结论（重点）

### 3.1 端口情况

| 端口 | 协议 | 实测结果 |
|---|---|---|
| UDP 3956 | 私有发现/应答 | 相机应答，可拿到完整设备信息（见 3.2） |
| TCP 23 | telnet 调试壳 | 开放，Linux 设备（BusyBox 风格，提示 `(none) login:`），需账号密码，非官方配置通道 |
| TCP 80/2048/3956/5000/8000/9000 等 | — | 未开放（扫描无响应） |

### 3.2 设备发现协议（已逆向可用，Node 可直接实现）

相机不响应标准 GVCP 的常规发现包（magic 0x42 的普通 ACK），但它会响应下面这种 EasyID 实际发送的发现包：

**请求（8 字节，发往 UDP 3956，可广播或单播）：**

```text
42 11 00 02 00 00 <req_id_hi> <req_id_lo>
```

- `42`：魔数
- `11`：flags（bit4=1 表示要完整设备信息；若 flags=01，相机只回 8 字节简短应答）
- `00 02`：命令 = DISCOVERY_CMD
- `00 00`：长度
- `<req_id>`：自增请求号，响应中会原样带回

**响应（256 字节，来自 100.100.100.100:3956）：**

```text
00 00 00 03 00 f8 <req_id 2字节>
00 02 00 00 80 00 00 01 00 00
24 52 6a 5c d3 4d                  <- MAC
c0 00 00 07                        <- 相机自身 IP 字段（本机值为 192.0.0.7，含义待确认）
c0 00 00 05                        <- 掩码字段（本机值为 192.0.0.5，含义待确认）
00 00 00 00                        <- 网关
64 64 64 64                        <- 实际 IP：100.100.100.100（ASCII "dddd"=100.100.100.100）
ff ff ff 00                        <- 255.255.255.0
00 ...（填充）
"Dahua Technology"                 <- 厂商
"DH-MV-RH7B00MG200"                <- 型号
"V1.002.0001.7.RA.20210705-210"    <- 固件
"Dahua Technology"
"6M0B158PAK00142"                  <- 序列号
00 ...（填充到 256 字节）
```

完整实测 HEX（256 字节）：

```text
0000000300f8103d0002000080000001000024526a5cd34dc0000007c000000500000000000000000000000064646464000000000000000000000000ffffff0000000000000000000000000000000000446168756120546563686e6f6c6f677900d60de97f000000fcd60de97f00000044482d4d562d5248374230304d47323030000de97f000000fcd60de97f00000056312e3030322e303030312e372e52412e32303231303730352d323130000000446168756120546563686e6f6c6f6779006168756120546563686e6f6c6f677900d60de97f000000fcd60de97f000000364d304231353850414b30303134320000000000000000000000000000000000
```

**另一个 40 字节包（EasyID 发现时同时发送，用途待确认）：**

```text
42 11 02 00 00 00 <req_id 4字节> 00 00 00 00 "General" + 填充到 40 字节
```

相机对此的应答为 8 字节：`80 0e 02 01 00 00 <req_id 2字节>`。

**结论**：Node 版可以用 UDP 广播 + 解析 256 字节响应实现“自动发现读码器”功能，不依赖华睿 SDK。

### 3.3 EasyID SDK 实测坑（重要）

- EasyID SDK（Python/C/C# 封装齐全，路径见第 6 节）在本机**枚举不到这台相机**：`eidEnumDevices` 与 `eidEnumDevicesByUnicast` 都返回 OK 但数量 0，即使相机空闲、EasyID GUI 已关闭。
- 尝试把 `EasyIDSDKConfig.json` 中 `standard_camera.discovery_enable` 改为 `true` 无效。
- 原因推测：SDK 1.1.0.398806 无法解析该机型私有发现应答，或依赖特定网卡过滤驱动绑定；EasyID 客户端（GUI）的发现逻辑更新、可以工作。
- **相机单客户端独占**：同一时刻只允许一个客户端连接；EasyID GUI 连着时，SDK/其它客户端再连会失败。
- 开发建议：**不要把设备发现/连接建立在 SDK 上**；v1 用读码器自带的 TCP 输出功能即可。

## 4. EasyID 连接与配置操作路径（官方说明书确认）

### 4.1 连接相机

1. 打开 EasyID，设备列表会自动发现同网段相机。
2. 若相机 IP 与工控机不同网段：鼠标悬停设备 → 点 IP 设置图标 → 输入同网段 IP → 确认。
3. 双击设备名（或点行右侧连接图标）→ 连接成功后自动拉流，图像区显示画面，结果区实时刷新解码信息（触发时间、解码耗时、码类别、码内容）。
4. 设备状态图标：绿=正常可连；灰/橙=被其他客户端占用、不同网段或离线。
5. 配置里可开“自动重连”；若相机已连接会提示连接失败。

### 4.2 配置 TCP 结果输出（抓报文前的必做步骤）

进入：`单设备配置 -> 全属性参数 -> 网络通信配置`

- 勾选 **传输使能**
- 网络模式 = **TCP客户端**
- 端口号 = 9000（自定义，20~65535）
- 服务器IP地址 = 100.100.100.10（DWS 上位机所在网卡）
- 网络保活：可选默认

进入：`单设备配置 -> 全属性参数 -> 结果传输配置`

- 传输方式选择 = **TCP结果打包**
- 勾选 **结果打包使能**
- 结果输出条件：全部输出 / 读码成功时输出 / 读码失败时输出 / 自定义
- 结果输出格式、输出结果开始格式、输出结果结束格式、结果分隔符、尾部数据：均可自定义（决定最终报文长什么样）

然后：`触发配置` 选自由运行或软件触发，放一个条码到镜头前，上位机监听端口即可收到报文。

## 7. 对 Node DWS v1 的设计影响

1. **数据接入**：每台读码器配置为 TCP 客户端，主动连 DWS 上位机的监听端口（每台一个端口或一台一个连接）。上位机用 `net` 模块即可，6 台并行。
2. **六面聚合**：优先验证读码器自带“多设备组网”功能——主相机按“输出绑定时间”把六面结果合并成一包输出，上位机只需解析一包；若现场不用组网，则 6 路分别解析后按时间窗/触发ID 合成一件。
3. **报文解析**：帧格式完全由“结果传输配置”决定（帧头/分隔符/帧尾/尾部数据/多码顺序），解析器参数化，把读码器配置做成可配置项。
4. **触发**：现场推荐外部光电触发（Line0/Line1）或 TCP/串口触发指令；DWS 用触发ID/时间窗聚合。
5. **去重与主码**：读码器自带“重复码过滤”和“结果过滤（正则）”，主码选择规则建议放上位机（优先级/长度/正则）。
6. **存图**：OK/NG 图片走 FTP 到上位机目录，v1 可留接口后置。
7. **设备发现**：Node 可用 UDP 3956 私有发现协议实现“一键发现读码器”，替代 EasyID 的设备列表。
