# DWS 业务逻辑总览

## 1. DWS 是什么

DWS = **D**imensioning（体积测量）+ **W**eighing（称重）+ **S**canning（读码），是物流分拨中心部署在传输皮带上的**自动化包裹信息采集设备**。大华这套系统（`LogisticsPlatform`，本目录即其安装目录）实现了：

1. 包裹在皮带上运行时，**自动触发相机抓拍**，读取包裹面单上的**一维码/二维码**；
2. 同步采集**重量**（动态称）与**体积**（3D 相机）；
3. 将"条码 + 重量 + 体积 + 图片"绑定为一个包裹数据包；
4. 按客户要求**过滤、格式化、输出**给上游系统（WMS/分拣机/快递公司平台）；
5. 保存**历史记录与图片**，提供**读码率/计泡率/漏称率/上传率**等统计。

## 2. 三大方案（Solution）

软件在"方案切换"向导中提供三种运行模式，决定启用的功能模块：

| 方案 | 称重 | 体积 | 读码 | 放包方式 | 典型场景 |
|---|---|---|---|---|---|
| **DWS 方案** | ✅ | ✅ | ✅ | 皮带自动 | 分拨中心全自动测量 |
| **快手 FastScan** | ✅ | 可选 | ✅ | 手动放包 | 揽收台、自动揽收 |
| **狂扫 RapidScan** | ❌ | ❌ | ✅ | 皮带/手持 | 只读码、批量扫描 |

> [!tip] 对 Node.js 重建的意义
> 用户 V1 只做读码，等价于实现"**狂扫方案**"。原系统狂扫方案仍然具备完整的：多相机采集、条码过滤规则、结果输出、历史统计、图片存储能力，只是不初始化称重/体积模块。

## 3. 功能能力清单（来自原系统 UI/配置）

### 3.1 采集层
- 支持**工业相机（GigE / USB3 Vision）**、**线扫相机**、**智能相机（自带读码）**、**全景相机（IPC）**混合组网；
- 相机触发方式：自由运行、硬触发（光电传感器）、软触发；
- 多相机自动发现、手动添加、连接测试、拉流测试、修改 IP；
- 断线自动重连、NTP 时间同步、帧率控制、双帧模式（PhaseMode）；
- 图像源模式：自动发现（mode=1）/ 指定 IP/Key（mode=2）/ 线扫（mode=3）/ 全部工业相机（mode=4）/ 混合（mode=5）；
- 包裹汇总：多相机按**时间窗**（首帧差、包裹间隔、汇总等待时长）合并为一次"过包"。

> [!note] 六面扫部署形态
> DWS 的典型部署是"六面扫"：在皮带隧道四周布置 **6 台相机**，分别覆盖**顶、底、左、右、前、后**六个面，保证面单无论朝向哪一面都能被读到。相机可以全部是**智能相机**（相机端解码，直接上报条码），也可以是普通工业相机（由本地 SDK 解码）。**V1 采用"智能相机六面扫"：本地只收码，不解码。**

### 3.1.1 相机方位标记
- 相机可通过 `userID`/标签标记方位（如 `fr` 开头=前相机、`ba` 开头=后相机），供条码方位过滤使用；
- 一个相机 IP 对应一个唯一 Key（序列号），多相机按 Key/IP 管理。

### 3.2 读码与过滤
- 一维码：EAN13、Code128、Code39、EAN8、UPCA、UPCE、Code93、ITF25、CODABAR、PDF417；
- 二维码：QR、DataMatrix（DM）、VC；
- 面单**抠图（Matting）**：从包裹原图中裁出条码区域/面单图；
- 条码过滤规则：字符类型（纯数字/纯字母/字母数字）、长度范围、前缀/后缀、排除前缀/后缀、正则表达式，支持多规则优先级组合（PlatformRules）；
- 内置快递单号规则库（`coderules.json`）：电子面单、YT 开头、R02 开头、12 位普通面单、B0/L/M/JY/BZB 等。

### 3.3 称重（V1 不需要，但记录原逻辑）
- 串口 / TCP 动态称；协议：静态称、通用动态称、梅特勒动态称、自定义协议称；
- 采样数、精度（克）、稳定超时、异步等待称重、先码后称/先称后码（QuickHand）；
- 通用协议可配置报文长度、有效位、帧头帧尾、单位换算（g/kg）。

### 3.4 体积（V1 不需要，但记录原逻辑）
- 动态 3D：线扫 3D 相机 + 深度图/点云 + 参考平面标定（`3DCfg/`）；
- 静态 3D：固定放置测量（`StaticVolume`）；
- 长宽高单位 mm，体积 mm³，支持包裹检测参数、稳定帧、去手干扰、托盘补偿等。

### 3.5 数据绑定（信息融合）
- 条码、重量、体积**三者按时间窗绑定**为同一包裹（minValidTime ~ maxValidTime）；
- 数据优先级：重量优先 / 条码优先；
- PLC 小车号绑定（PackageIDBinder）、RFID 绑定；
- 无码补录（弹框）、补重量、补体积。

### 3.6 输出
- 数据格式模板（`{Code},{Weight},{Length},...`，支持宏替换、十六进制）；
- TCP 客户端 / TCP 服务端 / 串口 / HTTP / 句柄输出 / 焦点输出 / Web 输出 / 音频 OK-NG / LED 显示屏；
- 图片上传：FTP / SFTP / HTTP，上传目录按时间模板分文件夹；
- 重传机制：最大上传次数、发送延迟、失败入库待重传。

### 3.7 图像存储
- 存储策略：所有包裹 / 有码 / 无码 / 多码；
- 图像源：原图 / 运单图（面单抠图）/ 全景图 / 所有相机图；
- 文件名模板：场地代码、线体号、条码、时间戳、包裹 ID、相机名、结果、物料码等；
- 文件夹模板（年/月/日/时），水印、JPEG 质量、保存天数、定期清理。

### 3.8 皮带与 PLC（V1 可不做）
- 滚动皮带类型：串口称（5/6 字节）、TCP 称、SF/科捷继电器、声光报警模块等；
- 心跳、补码模式/直通模式、无码停止、多码停止、超重/超轻停止等；
- PLC 类型：数十种快递设备商（顺丰、京东、邮政、中集、新北洋、伟创等）协议。

### 3.9 历史与统计
- 历史记录表：条码、重量、长宽高、体积、时间、上传状态、图片路径、异常信息；
- 统计指标：读码率、计泡率、漏称率、异常率、上传率、包裹总数；
- Excel 导出（手动 + 定时自动导出）。

### 3.10 系统管理
- 管理员登录（密码）、精简模式/完全模式；
- 配置导入/导出、方案切换、配置升级（旧配置自动迁移）；
- 日志（log4net + SQLite）、日志收集工具、相机固件升级、软件自动升级（Updater）；
- 加密狗授权、看门狗、开机自启、多语言（中/英/越）。

## 4. 角色与权限

- **管理员**：可修改全部配置（相机、算法、规则、输出、平台对接）；
- **操作员**：仅查看实时结果、历史、统计，可执行补码等操作。

## 5. 业务边界

- 本系统**不负责**包裹分拣执行（摆臂由 PLC/WCS 控制，本系统只给 PLC 发分拣信号）；
- 本系统**不负责**路由计算（路由/格口由上游平台查询，见 `RoutingList.json`、格口配置）；
- 本系统**必须**对接至少一个"平台插件"才具备完整业务闭环（如顺丰、京东、百世等），否则只能做本地数据采集。
