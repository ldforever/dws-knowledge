# DWS 上位机（Node.js v1）项目梳理与待确认问题

> 基于《7000系列读码器手册V1.0.pdf》整理；所有标注【待确认】的内容都需要你或厂家文档来落实，不靠猜测。

## 一、从手册确认的事实（读码器侧能力）

手册是 R7000 系列 AI 智能读码器（型号示例 R7200MG / R7201MG / R7250MG，20MP/25MP）的彩页规格书，确认以下几点：

- 读码器**自带解码能力**，可直接把条码内容通过以太网 / RS-232 输出给上位机，PC 端**不需要解码算法库**。
- 通讯协议：SDK、TCP Client、TCP Server、FTP、RS232、Profinet、Modbus、EtherNet/IP、MC(SLMP)、FINS/UDP、FINS/TCP。
- 触发方式：软件触发 / 外部触发 / 自由运行等；外部触发走 GPIO（3 路光耦隔离输入、3 路光耦隔离输出）。
- 单图最多解 128 个码，支持多区域 ROI，可按区域排序输出结果。
- 支持最多 8 组参数切换（自动换线场景用）。
- 支持读码图像保存（可按条件存图），千兆网口可传输"解码数据"和"解码失败存图"。
- 配套软件叫 Easy ID（读码器配置/调试用）。
- 一维码：Code39 / Code93 / Code128 / CodaBar / EAN8 / EAN13 / UPCA / UPCE / ITF25 / 2of5 / standard25 / GS1-128；
- 二维码：QR / Data Matrix / Micro QR / GS1 DM / GS1 QR / Vericode（Vericode 需额外许可）。

## 二、手册没有、必须向厂家/现场要的信息

这本手册是**产品彩页/规格书，不是通讯协议手册**。以下信息在手册里找不到，是 v1 能否动工的前提：

1. **解码结果输出报文的详细格式**：帧头/帧尾、字段分隔符、多码时的序号规则、CRC 等。来源：Easy ID 软件里的"输出格式"配置，或厂家提供的《读码器通讯协议手册》。
2. **TCP 具体参数**：端口号、TCP Client / TCP Server 各自的连接方向和心跳机制。
3. **实际机型确认**：你举例的型号是 `DH-MV-RH7800MG200`，但手册是 R7000 系列（R7200/R7250），两者型号体系不一致【待确认：你们现场实际是哪款？协议是否同一套？】。

## 三、v1 建议架构（只做上位机功能，不做本地解码）

```
┌──────────────────────────────────────────────────────────────┐
│ Node.js DWS 上位机 v1                                         │
│                                                              │
│  接入层                                                       │
│  ├─ 读码数据接收：6 路读码器 TCP（Client/Server 待定）        │
│  ├─ 报文解析：帧格式、多码拆分、断线重连                      │
│  ├─ 称重数据：电子秤（串口/网络，协议待定）                   │
│  └─ 体积数据：体积测量设备（协议待定，v1 可先留接口）          │
│                                                              │
│  聚合层                                                       │
│  ├─ 包裹建模：按触发信号/时间窗把六面结果合成一件             │
│  ├─ 去重：同包裹多面读到同一码只记一次                        │
│  └─ 主码规则：多码时按优先级/长度/正则选主条码                │
│                                                              │
│  业务层                                                       │
│  ├─ 包裹记录：条码+重量+体积+时间+流水号，本地 SQLite/JSON    │
│  ├─ 上传对接：WMS/ERP（HTTP API 待定）                        │
│  ├─ 异常处理：无码/称重失败/上传失败队列                      │
│  └─ 统计：读码率、件数、异常件（可后置）                      │
│                                                              │
│  界面层                                                       │
│  ├─ 实时监控：六面读码状态、当前包裹、最近记录                │
│  ├─ 配置页：读码器 IP/端口、串口、主码规则、触发方式          │
│  └─ 历史查询/报表（可后置）                                  │
└──────────────────────────────────────────────────────────────┘
```

技术选型建议（均可再议）：

- Node.js + TypeScript；
- TCP 接收：直接用 `net` 模块即可，6 路读码器各建一个连接；
- 串口（称重）：`serialport` 包（Windows 下需要装其驱动依赖，v1 可先模拟）；
- 本地存储：SQLite（`better-sqlite3`）；
- 界面：Web 前端（Vue/React，浏览器访问）或 Electron 桌面壳，二选一；
- 上传对接：`axios`/原生 `http`。

## 四、待确认问题清单

### A. 读码器与现场架构

1. 【必须】现场实际机型是哪款？R7000 系列还是 RH7800 系列？有没有厂家提供的《通讯协议手册》或 Easy ID 导出的报文样例？
2. 【必须】六面扫实际用几台读码器？6 台各管一面，还是 5 台+反光镜/共视场？每台的触发方式（自由运行 / 外部光电触发 / 软件触发）？
3. 【必须】读码器→上位机用 TCP Client（读码器主动连 PC）还是 TCP Server（PC 连读码器）？有没有一段真实解码输出报文样例？
4. 【建议】旧 DWS 软件里能看到读码器配置页吗？能截图或导出配置吗？这能直接确定协议细节。

### B. 称重与体积

5. 【必须】电子秤型号和接口：RS232 连续输出 / 命令查询 / 网络口？重量数据格式（稳定标志、小数点）？第一版必须接秤吗？
6. 【必须】体积测量用什么设备（光幕 / 3D 相机 / 激光测距）？接口协议是什么？v1 是否要体积，还是先留接口？
7. 【可选】有没有 PLC（输送线控制、光电、分流）？DWS 需要向 PLC 回传结果吗（Modbus TCP 写地址）？

### C. 业务与对接

8. 【必须】读码结果最终传到哪里：WMS/ERP 的 HTTP API？数据库（哪种）？有没有报文/字段样例？
9. 【必须】一个包裹的主码规则：六面可能读到多个码（重复或不同码），主条码怎么定（指定面优先 / 码长 / 正则 / 先到先得）？无码包裹怎么处理（异常队列 / 人工补录站）？
10. 【建议】v1 要不要保存读码图片（解码失败存图）做追溯？读码器存图一般走 FTP，可放 v1.1。

### D. 运行环境与界面

11. 【必须】部署在 Windows 工业 PC？允许装 Node.js 运行时吗？界面要桌面壳（Electron）还是局域网网页？
12. 【建议】原来 DWS 的功能里，哪些必须复刻、哪些可砍？（实时监控 / 六面状态 / 报表 / 配置 / 权限 / 补录 / 图片…）
13. 【建议】峰值件数/小时、历史数据保留多久，决定本地库和统计的复杂度。
